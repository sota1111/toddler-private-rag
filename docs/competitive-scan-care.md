# 個別配慮向け 既存サービス 競合スキャン（出典付き比較）

- 対象Issue: [SOT-2731](https://linear.app/sota-dev/issue/SOT-2731) — Deliverable 3 の「個別プロダクト名・機能の断定」部分を、実サービスの機能確認（出典付き）で確定する。
- 親Issue: [SOT-2728](https://linear.app/sota-dev/issue/SOT-2728)（個別配慮・アレルギー情報を踏まえた「うちの子専用」対応の改善計画）
- 調査日: 2026-08-20（各機能記述は同日に確認できた公開情報に基づく。**確認できた事実のみを記載し、未確認の機能は断定しない**。仕様は変更され得るため、下記の出典URLを一次情報とする。）

## 0. 調査の観点と方針

おたよりナビの改善方向（親Issue SOT-2728）は、単なる「おたよりの整理」ではなく、
**子どもごとに登録された個別配慮プロファイル（食物アレルギー＋非アレルギー配慮：音過敏・乗り物酔い・動物接触歴・喘息・服薬など）と、園・学校から届く情報（献立表・原材料表・行事案内・おたより）を照合し、「この子の場合に確認が必要なこと」を根拠付きで発見する**ことにある。実装済みの照合エンジン・要確認レーン・安全ガードは、それぞれ [SOT-2730](https://linear.app/sota-dev/issue/SOT-2730) / [SOT-2733](https://linear.app/sota-dev/issue/SOT-2733) / [SOT-2734](https://linear.app/sota-dev/issue/SOT-2734) / [SOT-2736](https://linear.app/sota-dev/issue/SOT-2736) で対応する。

そこで代替手段を次の3カテゴリに分けて実確認した。

1. 園・学校の連絡／おたより配信アプリ（国内・海外）
2. 食物アレルギー管理アプリ／サービス（国内・海外）
3. 汎用OCR・AIチャット（家庭で「おたよりを読み取る」用途に流用されているもの）

各カテゴリについて、**解決済み領域 / 不十分な領域 / おたよりナビの独自価値 / 補完できる部分** を整理する。

### 1-2. 解決済み領域

- 園・学校からの**情報配信の一元化**（おたより・献立・行事の電子配信、既読管理、添付ファイル閲覧）。CoDMON・ルクミー・ClassDojo・Brightwheel いずれも成熟している。
- CoDMON は献立配信に加え、**施設運営側**での卵・乳・小麦のアレルギー対応献立配信・アラートまで踏み込んでいる（[出典](https://www.codmon.com/service/lunch/)）。

### 1-3. 不十分な領域（確認した公開情報の範囲）

- これらは**「送る／表示する」側**が中心で、**受け取った保護者側で、届いた文面を子ども個人の事情に照らして読み替える**用途は、確認した公式ページの範囲では見当たらなかった。
  - ルクミーおたよりの公式ページ機能説明には、**OCR読み取り・内容の自動解析・個別事情との照合機能は記載がない**（[出典](https://lookmee.jp/letter/)。※記載がないことをもって将来も存在しないと断定はしない）。
- CoDMON のアレルギー機能は**卵・乳・小麦の代替献立配信および施設運営向けアラート**として確認でき、非アレルギーの個別配慮（音過敏・乗り物酔い・動物接触歴など）×行事案内の照合まで確認できる記述は、[給食管理ページ](https://www.codmon.com/service/lunch/)には見当たらなかった。
- 導入は**園・施設側の採用が前提**で、家庭が任意の園（未導入園・複数園・小学校移行後）を横断して使える保護者主導のツールとは性質が異なる。

### 2-2. 解決済み領域

- **食品・製品／外食メニューのアレルゲン特定**は成熟している。市販品のバーコード/商品DB照合（アレルギーチェッカー・e食なび）、原材料ラベルの撮影→アレルゲン判定（CAN EAT・アレルギー管理サービスアプリ）、コミュニティ型のレストラン情報（Spokin）と、用途別に選択肢が揃う。
- 公的な**知識・判断基準**はアレルギーポータル（日本アレルギー学会／厚労省補助）が担う（[出典](https://allergyportal.jp/)）。

### 2-3. 不十分な領域（確認した公開情報の範囲）

- これらは**「食品／メニューの中身を調べる」軸**であり、**「園・学校から届いた文書（献立表・行事案内・おたより）を、その子の登録プロファイルに照らして確認候補を発見する」軸**とは対象が異なる。CAN EAT・アレルギー管理サービスアプリは**外食事業者向け**であり（[出典1](https://biz.caneat.jp/allergenlist/) / [出典2](https://apps.apple.com/jp/app/%E3%82%A2%E3%83%AC%E3%83%AB%E3%82%AE%E3%83%BC%E7%AE%A1%E7%90%86%E3%82%B5%E3%83%BC%E3%83%93%E3%82%B9%E3%82%A2%E3%83%97%E3%83%AA/id1549610695)）、園・学校のおたより・行事予定との照合機能への言及は、確認したページには見当たらなかった。
- 対象は基本的に**食物アレルギー**であり、**非アレルギーの個別配慮**（音過敏×運動会、乗り物酔い×バス遠足、動物接触歴×ふれあい体験、喘息×長時間屋外、服薬×宿泊行事 等）は、これらアレルギー特化サービスのスコープ外である。
- 安全設計の観点で、**情報不足・曖昧な記載を「断定せず確認を促す」体験**を主目的に据えたものは、確認した範囲では見当たらなかった（多くは「含む／含まない」の判定提示に主眼）。

## 3. 汎用OCR・AIチャット（家庭での流用）

### 3-1. 確認できた実態（出典付き）

| ツール | 家庭での使われ方（確認できた範囲） | 出典 |
| --- | --- | --- |
| **Google Lens** | 画像内テキストのOCR。おたより等の文字を読み取りコピー可能。 | [Google Lens OCR活用](https://docs.kaiji-lab.com/posts/google-lens/) |
| **ChatGPT（画像入力／Vision）** | おたより画像から**行事予定・持ち物・締切等を抽出**し箇条書き化、Zapier等でカレンダー連携する実践例。ただし**プライバシー面の設定注意**（モデル学習のオプトアウト）が必要と解説。 | [OCR→カレンダー連携（Qiita）](https://qiita.com/sugino-k/items/1bef87c3a20d66bab93b) / [ChatGPTのOCR機能と注意点](https://biz.moneyforward.com/ai/basic/3791/) |

### 3-2. 解決済み領域

- **文書のOCR＋汎用的な要約・抽出**は、Google Lens＋ChatGPT の組合せで家庭でも実現可能。予定・持ち物・締切の箇条書き化まではカバーされる（[出典](https://qiita.com/sugino-k/items/1bef87c3a20d66bab93b)）。

### 3-3. 不十分な領域（確認した公開情報の範囲）

- **子どもごとの個別配慮プロファイルを永続保持し、届いた文書と自動照合して「この子向けの確認候補」を継続的に発見する**仕組みは、汎用ツールの標準機能としては確認できなかった（毎回プロンプトで個別事情を与える手作業に依存）。
- **安全設計（断定禁止・情報不足時の棄権・根拠提示・情報の鮮度考慮）**が組み込まれておらず、汎用LLMは断定的な回答をしやすい。健康・アレルギー領域では誤った安心を与えるリスクがある。
- **プライバシー**：家庭の個別配慮（健康情報）を汎用チャットに継続投入することには、学習オプトアウト等の設定配慮が必要と明示されている（[出典](https://biz.moneyforward.com/ai/basic/3791/)）。

## 4. 総合：おたよりナビの独自価値と補完領域

### 4-1. 独自価値（確認した競合の範囲では見当たらなかった組合せ）

確認した各サービスは、いずれかの「軸」を担うが、**次の3点を同時に満たす体験**は、調査した範囲では確認できなかった。

1. **個別配慮プロファイル × 届いた文書の照合**：食物アレルギーだけでなく、音過敏・乗り物酔い・動物接触歴・喘息・服薬などの**非アレルギー配慮も含む**プロファイルを、園・学校から届く献立/行事/おたよりと照合する。
   - アレルギー特化サービス（CAN EAT・アレルギーチェッカー 等）は**食品/メニューの中身**が対象で、園文書×個別配慮の照合ではない（[§2-3](#2-3-不十分な領域確認した公開情報の範囲)）。
   - 園連絡アプリ（CoDMON・ルクミー 等）は**配信**が中心で、受信文書の個別読み替えは確認できなかった（[§1-3](#1-3-不十分な領域確認した公開情報の範囲)）。
2. **根拠提示付きの「確認候補」提示（断定しない）**：「安全／食べられる」等の断定を避け、「登録済みの◯◯と関連する記載があるため確認が必要」という形で、根拠となった文書箇所を示す。実装は要確認レーン [SOT-2734](https://linear.app/sota-dev/issue/SOT-2734) と安全ガード [SOT-2736](https://linear.app/sota-dev/issue/SOT-2736)。
3. **安全側の設計（棄権・鮮度警告）**：情報不足・曖昧時は断定せず棄権し、無関係文書には過剰警告を出さない。プロファイルの古さには鮮度警告を出す（[SOT-2736](https://linear.app/sota-dev/issue/SOT-2736)）。汎用OCR/AIには標準では備わらない（[§3-3](#3-3-不十分な領域確認した公開情報の範囲)）。

加えて、園の導入に依存せず**保護者主導**で、複数園・小学校移行後も含めて使える点が、施設採用前提の園連絡アプリと差別化される。

### 4-2. 置き換えず補完できる部分

おたよりナビは既存サービスを置き換えるものではなく、**受け取った情報の上に「この子向けの確認候補」を重ねる**位置づけで補完関係にある。

- **園連絡アプリ（CoDMON/ルクミー/ClassDojo/Brightwheel）**：配信・既読管理はそのまま。おたよりナビは、そこで配布された文書を保護者側で個別読み替えする層を担う。
- **食品/メニューのアレルゲン特定（アレルギーチェッカー/CAN EAT/e食なび/Spokin）**：市販品や外食の可否確認はこれらが得意。おたよりナビは「園の献立/行事のどれを確認すべきか」を絞り込み、詳細な製品可否は既存アプリや保護者・専門職の判断へ橋渡しする。
- **汎用OCR/AI（Google Lens/ChatGPT）**：単発の読み取り・要約には有用。おたよりナビは、個別プロファイルの永続保持と安全設計を加えて、継続運用・見落とし低減の信頼性を担保する。
- **公的知識（アレルギーポータル）／医療専門職**：最終的な医療判断・診断はサービスが代替しない。おたよりナビは「確認を促す」までを担い、判断は保護者・園・医療へ委ねる（責任境界）。

### 4-3. 競合する部分（差分の明確化）

- CoDMON の**献立×アレルギー機能**とは、食物アレルギー×献立の一部で機能が重なる。ただし CoDMON は**施設導入前提・卵乳小麦中心・運営向けアラート**であり、おたよりナビは**保護者主導・非アレルギー配慮も含む・根拠付き確認候補**である点で棲み分く（[出典](https://www.codmon.com/service/lunch/)）。
- 汎用AIチャットは「おたよりを読んで予定を出す」導線が重なるが、**個別配慮の永続照合と安全設計**の有無が差分（[§3](#3-汎用ocraiチャット家庭での流用)）。
